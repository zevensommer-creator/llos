# LLOS 产品规格（Product Specification）

> **目的**：定义 LLOS 第一代产品"向谁提供什么"——用户、权限、市场、训练与语音的产品层需求。
> **范围**：仅产品需求。系统如何构建由 [`LANGUAGE_PLATFORM_SPEC.md`](./LANGUAGE_PLATFORM_SPEC.md)（架构基线 v0.1.1）管辖。
> **版本**：0.2（累积草稿） · **日期**：2026-08-15 · **维护**：Human + TRAE
>
> **与架构基线的关系**：本文件与架构基线互补。基线管"系统怎么建"（Core/DLC 编译器/Material Pack/Learning IR/Provider），本文件管"产品卖什么、给谁用"（权限/市场/班级/训练体验）。两者冲突时，架构不变量优先，产品需求通过 ADR 流程修订。
>
> **重要术语对齐**：本文件中的"DLC"遵循架构基线定义——**教学编译器**，不是课程内容包。市场展示层可向用户呈现为"学习内容包"，但其内部构成是"编译器 + 素材包（Material Pack）"。

---

## 1. 产品定位

- LLOS 是**语言学习编译平台**（定义与架构原则见基线第 0、1 章）。
- 目标是**完整第一代产品**，不是 Demo，不是 MVP。
- 性价比须显著优于传统教师和传统网课。

### 目标用户

| 用户群 | 说明 |
|--------|------|
| 高校教师与学生 | 教师组织班级、分配学习内容、跟踪进度 |
| 非组织个人学习者 | 自由学习者，自选内容、自定节奏 |

> 决策记录（2026-08）：产品不只服务高校，必须同时服务非组织人员。多语言通过市场分类解决，不设语言门槛。

---

## 2. 权限模型（能力点制）

> 决策记录（2026-08-10）：不设层级，能力打散为独立能力点；教师与自由 DLC 开发者在 DLC Studio 中无差别，教师仅多班级管理权限；学生权限所有用户都有。

### 2.1 能力点清单

| 能力 ID | 名称 | 获取方式 | 说明 |
|---------|------|---------|------|
| `learn` | 学习 DLC | 注册即获得 | 使用已发布的 DLC 进行训练 |
| `publish_dlc` | 发布 DLC | 注册即获得 | 上传、测试、公开发布 DLC，**无需审核**（只要做得出来就能发） |
| `join_class` | 加入班级 | 注册即获得 | 通过班级邀请码加入 |
| `create_class` | 创建班级 | 班级邀请码 | 创建班级、生成新邀请码、管理自己的班级 |
| `review_dlc` | 审核/下架 DLC | 开发者授权 | 下架违规 DLC、标记质量 |
| `manage_users` | 用户管理 | 开发者授权 | 查看/封禁用户、授予/撤销能力点 |
| `system_config` | 系统配置 | 开发者授权 | 平台参数、模型配置 |
| `global_stats` | 全局统计 | 开发者授权 | 查看全平台数据 |

### 2.2 关键规则

- **能力叠加、可单独撤销**：能力点独立获取与撤销，不是互斥层级。
- **邀请码链式传播**：持有 `create_class` 的用户可生成班级邀请码；被邀请者获得 `create_class` 后可继续生成（2026-08-10 确认：L1 以上都能生成）。
- **开发者可多人**：最高权限（`review_dlc`/`manage_users`/`system_config`/`global_stats`）可按需组合授权给多个开发者，也可撤销。
- **DLC 发布零审核**：质量由市场评分与下载量自然筛选（类似 Steam 创意工坊）。违规内容由 `review_dlc` 能力事后处理。

## 3. DLC 市场

> 决策记录（2026-08-10）：分类、付费与评价规则。

### 3.1 发现与筛选

| 维度 | 类型 | 说明 |
|------|------|------|
| 语言 | **主分类** | 德语、英语、法语、俄语等（发布顺序见第 6 节） |
| 评分 | 筛选项 | 订阅者评分 |
| 下载量 | 筛选项 | 热度排序 |
| 难度等级 | 可选筛选项 | 如 A1–C2 |
| 应用场景 | **自由标签** | 通用、机械、会议、外交、文学、学术等；创作者自定义，不作为独立分类方法 |

### 3.2 付费规则

| 场景 | 规则 |
|------|------|
| 免费 DLC | 任何人免费订阅 |
| 付费 DLC | 订阅需付费（付费功能第一版必须有） |
| 创作者的班级成员 | **自动免费**——不得出现"老师创作了 DLC，自己的学生还要付费"的情况 |
| 免费码 | 创作者可生成免费码/邀请码，发给特定用户避开收费 |
| 开发者自营 DLC | 项目发起人（开发者）先出免费的 |

### 3.3 评价规则

- 所有**已订阅者**（含免费获取者）都能评价。
- 未订阅者不能评价。

### 3.4 与架构基线的衔接

市场售卖/分发的单位在实现上是"DLC 编译器 + Material Pack"的组合授权（授权、购买记录、订阅状态由 Core 特权管理，见基线 P-001 与 2.1 节）。用户界面呈现为"学习内容包"即可。

## 4. 学习与训练

> 决策记录（2026-08-10/11）：训练框架与记忆科学要求。

### 4.1 Core 提供的通用训练能力

| 能力 | 说明 |
|------|------|
| 训练执行引擎 | 通用框架，执行 DLC 声明的任意训练模式 |
| 训练模式注册 | DLC 可定义**任意自定义训练模式**，Core 负责调度执行 |
| 间隔重复调度器 | 管理每个知识点的复习时间表，**避免瞬时记忆被误判为记忆成功**（按遗忘曲线逐步确认掌握） |
| 学习曲线追踪 | 区分"刚学会"与"已巩固" |
| 薄弱点分析 | 识别薄弱知识点并推荐针对性训练 |
| 自适应难度 | 答对加难、答错降难或回退复习 |

### 4.2 DLC 定义的内容

训练模式定义、知识点结构、评分规则、难度参数——全部属于 DLC，Core 不感知具体语言与理论（架构红线）。

### 4.3 与架构基线的衔接

- 训练执行对应基线的 Executable Session IR 执行与追加式学习事件。
- 间隔重复的调度证据（如 `review.scheduled`、`mastery.evidence_added`）走学习事件流；掌握度由确定性 reducer 计算，不由 LLM 直接填写。
- 间隔重复算法、学习曲线与薄弱点推荐的具体设计属于产品层，基线未展开，需后续专项细化（见第 7 节）。

## 5. 语音交互

> 决策记录：选型研究见 [`语音交互方案与发音评价研究.md`](./语音交互方案与发音评价研究.md)；**最终决策已由架构基线 ADR-004/005/007 做出**，研究文档中的"待决策 A/B/C"作废。

- 采用**本地开源链**：Silero VAD → faster-whisper → 词典/G2P → MFA 强制对齐 → GOP/CTC 证据 → Praat/Parselmouth 韵律 → 语言专用校准器 → 结构化评价 → 规则模板或受约束 LLM 解释。
- 首版重点：朗读/跟读（text-dependent），其次受约束表达；自由表达只给保守的可懂度/流利度证据。
- 评价必须证据化、可弃权；误纠正率优先于覆盖率。
- LLM 不得直接给发音打分（只把结构化证据转成反馈）。

## 6. 语言优先级

> 来源：架构基线 ADR-006（ACCEPTED）。

1. **德语首发**（首个真实产品闭环）。
2. 英语、法语、俄语为第二批次。
3. 英语公开数据（SpeechOcean762 等）仅作离线工程验证轨，不改变产品首发顺序。
4. 第二批语言共享协议，但不共享未经验证的阈值与校准器（基线 9.6 节上线门槛）。
