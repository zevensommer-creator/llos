# LLOS 产品规格（Product Specification）

> **目的**：定义 LLOS 第一代产品"向谁提供什么"——用户、权限、市场、训练与语音的产品层需求。
> **范围**：仅产品需求。系统如何构建由 [`LANGUAGE_PLATFORM_SPEC.md`](./LANGUAGE_PLATFORM_SPEC.md)（架构基线 v0.1.1）管辖。
> **版本**：0.4（累积草稿） · **日期**：2026-08-15 · **维护**：Human + TRAE
>
> **与架构基线的关系**：本文件与架构基线互补。基线管"系统怎么建"（Core/DLC 编译器/Material Pack/Learning IR/Provider），本文件管"产品卖什么、给谁用"（权限/市场/班级/训练体验）。两者冲突时，架构不变量优先，产品需求通过 ADR 流程修订。
>
> **重要术语对齐**：本文件中的"DLC"遵循架构基线定义——**教学编译器**，不是课程内容包。市场展示层可向用户呈现为"学习内容包"，但其内部构成是"编译器 + 素材包（Material Pack）"。

---

## 1. 产品定位

- LLOS 是**语言学习编译平台**（定义与架构原则见基线第 0、1 章）。
- 目标是**完整第一代产品**，不是 Demo，不是 MVP。
- 性价比须显著优于传统教师和传统网课。

### 目标用户

| 用户群 | 说明 |
|--------|------|
| 高校教师与学生 | 教师组织班级、分配学习内容、跟踪进度 |
| 非组织个人学习者 | 自由学习者，自选内容、自定节奏 |

> 决策记录（2026-08）：产品不只服务高校，必须同时服务非组织人员。多语言通过市场分类解决，不设语言门槛。

---

## 2. 权限模型（能力点制）

> 决策记录（2026-08-10）：不设层级，能力打散为独立能力点；教师与自由 DLC 开发者在 DLC Studio 中无差别，教师仅多班级管理权限；学生权限所有用户都有。

### 2.1 能力点清单

| 能力 ID | 名称 | 获取方式 | 说明 |
|---------|------|---------|------|
| `learn` | 学习 DLC | 注册即获得 | 使用已发布的 DLC 进行训练 |
| `publish_dlc` | 发布 DLC | 注册即获得 | 上传、测试、公开发布 DLC，**无需审核**（只要做得出来就能发） |
| `join_class` | 加入班级 | 注册即获得 | 通过班级邀请码加入 |
| `create_class` | 创建班级 | 班级邀请码 | 创建班级、生成新邀请码、管理自己的班级 |
| `review_dlc` | 审核/下架 DLC | 开发者授权 | 下架违规 DLC、标记质量 |
| `manage_users` | 用户管理 | 开发者授权 | 查看/封禁用户、授予/撤销能力点 |
| `system_config` | 系统配置 | 开发者授权 | 平台参数、模型配置 |
| `global_stats` | 全局统计 | 开发者授权 | 查看全平台数据 |

### 2.2 关键规则

- **能力叠加、可单独撤销**：能力点独立获取与撤销，不是互斥层级。
- **邀请码链式传播**：持有 `create_class` 的用户可生成班级邀请码；被邀请者获得 `create_class` 后可继续生成（2026-08-10 确认：L1 以上都能生成）。
- **开发者可多人**：最高权限（`review_dlc`/`manage_users`/`system_config`/`global_stats`）可按需组合授权给多个开发者，也可撤销。
- **DLC 发布零审核**：质量由市场评分与下载量自然筛选（类似 Steam 创意工坊）。违规内容由 `review_dlc` 能力事后处理。

## 3. DLC 市场

> 决策记录（2026-08-10）：分类、付费与评价规则。

### 3.1 发现与筛选

| 维度 | 类型 | 说明 |
|------|------|------|
| 语言 | **主分类** | 德语、英语、法语、俄语等（发布顺序见第 8 节） |
| 评分 | 筛选项 | 订阅者评分 |
| 下载量 | 筛选项 | 热度排序 |
| 难度等级 | 可选筛选项 | 如 A1–C2 |
| 应用场景 | **自由标签** | 通用、机械、会议、外交、文学、学术等；创作者自定义，不作为独立分类方法 |

### 3.2 付费规则

> 决策记录（2026-08-15）：买断与订阅并存，由创作者选择；免费码支持永久或限期。

| 项目 | 规则 |
|------|------|
| 计费模式 | 创作者按 DLC 选择：**免费 / 买断（一次性付费，永久访问）/ 订阅（周期计费）** |
| 创作者的班级成员 | **自动免费**——不得出现"老师创作了 DLC，自己的学生还要付费"的情况 |
| 免费码 | 创作者可生成，**永久或限期**两种，发给特定用户避开收费 |
| 开发者自营 DLC | 项目发起人（开发者）先出免费的 |
| 付费功能 | 第一版必须有 |

### 3.3 评价规则

- 所有**已获取用户**（买断、有效订阅、含免费获取者）都能评价。
- 未获取的用户不能评价。

### 3.4 与架构基线的衔接

市场售卖/分发的单位在实现上是"DLC 编译器 + Material Pack"的组合授权（授权、购买记录、订阅状态由 Core 特权管理，见基线 P-001 与 2.1 节）。用户界面呈现为"学习内容包"即可。

## 4. 班级系统

> 决策记录（2026-08-15）：Q1-Q4 全部定案。

### 4.1 定位

班级是"教师组织学生学习"的核心载体。任何持有 `create_class` 能力的用户都可创建班级（获取方式见第 2 节）。

### 4.2 班级功能（第一代）

| 功能 | 说明 |
|------|------|
| 分配 DLC | 教师选定 DLC（编译器 + 素材包组合），班级成员获得访问权 |
| 进度跟踪 | 查看每个成员完成了哪些训练、知识点掌握度 |
| 班级统计 | 整体完成率、薄弱点分布、训练时长 |
| 成员管理 | 邀请、移除成员 |
| 通知 | 教师发通知（如"本周完成第 3 课"） |

**第一代不做**：班级讨论区——社交功能不是训练系统的核心，且内容审核成本高。

### 4.3 付费 DLC 分配模式（C 方案：两种都支持）

教师给班级分配**他人创作的付费 DLC** 时，二选一：

| 模式 | 规则 | 适用场景 |
|------|------|---------|
| 教师为班级购买 | 教师批量购买班级授权，学生免费访问 | 高校采购 |
| 推荐自购 | 学生自己付费订阅，教师只推荐 | 自由学习者班级 |

> 注意：班级管理者**自己创作**的 DLC，其班级成员自动免费（见 3.2），无需购买。

### 4.4 成员管理

| 规则 | 决策 |
|------|------|
| 邀请方式 | 班级邀请码（复用能力点邀请码机制：教师生成、学生输入即加入） |
| 学生主动退出 | 允许；退出后失去该班级 DLC 的班级授权（已付费的个人订阅保留） |
| 教师移除成员 | 允许 |
| 多班级 | 一个学生可同时属于多个班级 |

### 4.5 DLC 分配模式

| 规则 | 决策 |
|------|------|
| 获得方式 | 免费 DLC 分配后自动获得；付费 DLC 按 4.3 模式走 |
| 学习顺序 | 教师可设置先修顺序（完成 A 才解锁 B）；仅班级内生效，自由学习者不受约束 |
| 截止日期 | 教师可设置；截止只影响班级统计中的"按时完成率"，**不锁定**学习权利——过期仍可学，标记为逾期 |

### 4.6 与架构基线的衔接

- 班级授权、批量购买记录属于 Core 特权（基线 P-001、2.1 节）：班级分配本质是 entitlement 发放，DLC/Agent/前端不得直写。
- 班级统计从学习事件投影派生，前端只读投影，不直接查询原始事件。

## 5. DLC Studio 与 DLC 生命周期

> 决策记录（2026-08-15）：Studio 设计方向与生命周期 Q1-Q4 定案。
> 背景：架构基线未覆盖 Studio 设计（仅旧 V1.0 提及职责归属），本章为产品层新设计，技术实现约束仍遵循基线。

### 5.1 定位与设计目标

- Studio 是创作者（教师与自由开发者无差别）设计、编辑、验证、发布 DLC 的入口。
- 设计目标有两个，且必须同时满足：
  1. **不懂计算机的老师能用**——全程表单与自然语言，不接触编译器/schema/IR 概念；
  2. **最大化解放创造力**——教学思想来源不受限制。

### 5.2 创作输入：不设限制

- 教学法选择**不限于预设模板**。创作者可从任意思想来源上传：PDF、PNG（含 OCR）、纯文字输入、Obsidian 笔记、ChatGPT/NotebookLM 导出内容、个人教学经验、学术著作等。
- 系统提供摄入管线：格式解析（PDF/PNG/文本）→ AI 辅助结构化（经 Provider Gateway）→ 生成 DLC 草稿（manifest + Material Pack）→ 创作者在表单中确认与调整。
- 预设模板作为**可选加速器**存在，不是必经入口。
- 一切草稿必须通过 schema 校验才能发布；校验失败的提示必须翻译成教学语言（如"第 2 课的音频没有对应文本，请补充"），不得暴露技术错误。

### 5.3 参数设置

- 训练时长为**建议时长**，不是硬性约束。
- "硬性难度晋级时长"（学满多久才允许晋级）为**可选项**，由创作者决定是否启用。

### 5.4 试用

- 发布前，创作者可以模拟学生身份完整走一遍训练流程，称为"**试用**"。
- 试用在沙箱执行（编译 → Executable IR → 沙箱运行），不产生真实学习事件。

### 5.5 算力与模型计费（BYOK）

- Studio 的 AI 辅助（摄入、结构化、生成）**默认不消耗平台算力**。
- 创作者二选一：
  - 使用平台算力（计量与计费规则待定）；
  - **自带 API key（BYOK）**，兼容多家公司。
- 多供应商接口设计可调研复用 DeepSeek Harness 的开源多 Provider 接口（见第 9 节待决）。
- 无论算力来源，所有模型调用必须经过 Provider Gateway（架构不变量）；BYOK 密钥由 Gateway 统一保管并声明隐私级别。

### 5.6 双模式

| 模式 | 面向 | 能力 |
|------|------|------|
| 向导模式（默认） | 不懂计算机的老师 | 上传 → 表单 → 试用 → 发布 |
| 专家模式（可选） | 技术型创作者 | 直接编辑 manifest、自定义训练模式 |

### 5.7 版本管理（对创作者隐形）

- DLC 与 Material Pack 均使用语义化版本；DLC 声明其兼容的 Material Pack 版本范围。
- 创作者只做"保存"与"发布更新"，**从不接触版本号**；系统自动判定版本类型（素材/文案变更 → patch/minor；教学结构变更 → major）。
- 发布更新前，系统自动用参考素材包跑编译校验，通过才允许发布。
- 已获取用户进行中的训练会话锁定在其获取时的版本组合，不被升级打断。

### 5.8 更新推送

- **全部自动更新**（A 方案，Steam 游戏式），含 major 版本。

### 5.9 下架规则

**DLC 与 Material Pack 均适用：**

| 场景 | 规则 |
|------|------|
| 创作者主动下架 | 停止新获取；**已获取用户（买断/有效订阅）保留访问权** |
| `review_dlc` 强制下架（违规） | 立即对所有人不可见；已获取用户的处理（退款或保留）待定 |
| Material Pack 被下架且有 DLC 依赖 | 该 DLC 标记"素材缺失"，暂停新获取；已获取且本地已有素材者继续可用 |

**创作者告知义务**：发布时必须明确知晓——用户的获取是长期授权，下架只影响新用户，不收回既有用户权利（买断用户尤其如此）。

### 5.10 创作者离场

- 默认：DLC 转**无主状态**继续可获取使用，标记"停止维护"。
- 开发者（平台方）有权接管重要 DLC，指定接手人。

### 5.11 与架构基线的衔接

- Studio 的 AI 辅助全部经 `gateway/`；BYOK 密钥的存储与隐私级别声明属 Core 特权。
- 摄入管线的产物必须通过 schema 校验才能成为合法 DLC/Material Pack。
- 授权、购买记录、下架状态由 Core 特权管理（基线 P-001、2.1 节），Studio 与前端不得直写。

## 6. 学习与训练

> 决策记录（2026-08-10/11）：训练框架与记忆科学要求。

### 6.1 Core 提供的通用训练能力

| 能力 | 说明 |
|------|------|
| 训练执行引擎 | 通用框架，执行 DLC 声明的任意训练模式 |
| 训练模式注册 | DLC 可定义**任意自定义训练模式**，Core 负责调度执行 |
| 间隔重复调度器 | 管理每个知识点的复习时间表，**避免瞬时记忆被误判为记忆成功**（按遗忘曲线逐步确认掌握） |
| 学习曲线追踪 | 区分"刚学会"与"已巩固" |
| 薄弱点分析 | 识别薄弱知识点并推荐针对性训练 |
| 自适应难度 | 答对加难、答错降难或回退复习 |

### 6.2 DLC 定义的内容

训练模式定义、知识点结构、评分规则、难度参数——全部属于 DLC，Core 不感知具体语言与理论（架构红线）。

### 6.3 与架构基线的衔接

- 训练执行对应基线的 Executable Session IR 执行与追加式学习事件。
- 间隔重复的调度证据（如 `review.scheduled`、`mastery.evidence_added`）走学习事件流；掌握度由确定性 reducer 计算，不由 LLM 直接填写。
- 间隔重复算法、学习曲线与薄弱点推荐的具体设计属于产品层，基线未展开，需后续专项细化（见第 9 节）。

## 7. 语音交互

> 决策记录：选型研究见 [`语音交互方案与发音评价研究.md`](./语音交互方案与发音评价研究.md)；**最终决策已由架构基线 ADR-004/005/007 做出**，研究文档中的"待决策 A/B/C"作废。

- 采用**本地开源链**：Silero VAD → faster-whisper → 词典/G2P → MFA 强制对齐 → GOP/CTC 证据 → Praat/Parselmouth 韵律 → 语言专用校准器 → 结构化评价 → 规则模板或受约束 LLM 解释。
- 首版重点：朗读/跟读（text-dependent），其次受约束表达；自由表达只给保守的可懂度/流利度证据。
- 评价必须证据化、可弃权；误纠正率优先于覆盖率。
- LLM 不得直接给发音打分（只把结构化证据转成反馈）。

## 8. 语言优先级

> 来源：架构基线 ADR-006（ACCEPTED）。

1. **德语首发**（首个真实产品闭环）。
2. 英语、法语、俄语为第二批次。
3. 英语公开数据（SpeechOcean762 等）仅作离线工程验证轨，不改变产品首发顺序。
4. 第二批语言共享协议，但不共享未经验证的阈值与校准器（基线 9.6 节上线门槛）。
